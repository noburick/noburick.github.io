## 1. 目的

Noburick Realmの作品、開発方針、今後の展開をひとつの世界観で紹介し、各作品の詳細ページやストア、公式Xへ案内する。

サイト全体は「Small games, little adventures.」を合言葉に、猫との暮らしや小さなアイデアから生まれる個人開発レーベルらしさを伝える。

## 2. デザイン方針

- 温かい水彩・ガッシュの絵本風
- クリーム色と深緑を基調とする
- 猫、植物、木造の家、庭などを主要モチーフとする
- 見出しは手書き風、本文は読みやすい日本語書体とする
- 派手な演出よりも、落ち着き、親しみ、手作り感を優先する
- 角丸カードと控えめな影を使い、柔らかい印象に統一する

## 4. 各セクションの仕様

### 4.1 ヘッダー

- 左側に芽のアイコンと「Noburick Realm」を表示する。
- ナビゲーション項目は「作品一覧」「開発について」「日々のこと」とする。
- 各項目はページ内の対応セクションへ移動する。
- 画面幅700px以下ではハンバーガーメニューに切り替える。
- メニューはボタンの再タップ、リンク選択、Escapeキーで閉じる。

### 4.2 ヒーロー

- 背景画像は `images/realm-hero-walk.webp` を使用する。
- 画像には、ひなたと3匹の猫が庭の小道を自然に歩く場面を使用する。
- 表示テキスト:
  - ブランド名: `Noburick Realm`
  - キャッチコピー: `Small games, little adventures.`
  - 説明: `ゲームやアプリを、ひとつずつ。猫たちとの日常や、小さなアイデアから生まれた作品を作っています。`
- 「作品を見る」ボタンから `#works` へ移動する。
- PCでは人物と猫を左側、コピーを右側に見せる。
- 900px以下では画像全体を上部に置き、その下にコピーを表示する。
- ヒーロー画像はSNS共有画像（OGP）にも使用する。

### 4.3 作品一覧

- 見出しは「Our Works」「Noburick Realmの作品」とする。
- 作品データは `apps.js` の `appCatalog` で一元管理する。
- 一覧は常時2列のカード形式とし、スマートフォンでも2列を維持する。
- 各カードには次を表示する。
  - 代表画像（16:9）
  - 配信状態
  - 作品名
  - 短い説明
  - ストアまたは詳細ページへのボタン
- JavaScriptが無効な場合は、`noscript` 内の主要作品リンクを表示する。

## 5. 作品データ仕様

作品の追加・変更は原則として `apps.js` の `appCatalog` を編集する。

```js
{
  title: "作品名",
  summary: "作品の短い説明",
  status: STATUS.released,
  image: "./images/example-card.png",
  href: "ストアまたは詳細ページのURL",
  detailHref: "./apps/example/"
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `title` | 必須 | カードに表示する作品名 |
| `summary` | 必須 | 1〜2文程度の短い説明 |
| `status` | 必須 | `released`、`testing`、`developing` のいずれか |
| `image` | 必須 | 代表画像のパス。推奨比率16:9 |
| `href` | 必須 | 主ボタンのリンク。未公開時は空文字 |
| `detailHref` | 任意 | 主ボタンとは別に「詳細を見る」を追加する場合のリンク |

### 状態表示

| 値 | 表示 | ボタンの基本動作 |
|---|---|---|
| `STATUS.released` | 配信中 | URLに応じてApp Store、Google Play、詳細を見るを自動判定 |
| `STATUS.testing` | テスター募集中 | 詳細を見る |
| `STATUS.developing` | 開発中 | `href` が空ならComing Soon |

- 外部URLは新しいタブで開き、`noopener noreferrer` を付与する。
- `detailHref` がある場合は、副ボタンを主ボタンの前に表示する。
- 作品を増減した場合は、JavaScript無効時の `noscript` の案内も更新する。

## 6. レスポンシブ仕様

| 画面幅 | 主な表示 |
|---|---|
| 901px以上 | ヒーロー画像を全面背景にし、コピーを右側へ重ねる |
| 900px以下 | ヒーロー画像を上、コピーを下に分離する |
| 700px以下 | ハンバーガーメニュー、Aboutを1列化、余白と文字サイズを縮小する |
| 360px以下 | ブランド名、作品カード、余白をさらに微調整する |

- 基本コンテンツ幅は最大1040pxとする。
- 作品カードは全画面幅で2列を維持する。
- 320px幅でも横スクロールを発生させない。

## 7. アクセシビリティ仕様

- ページ先頭に「本文へ移動」のスキップリンクを設置する。
- 主要セクションは見出しと `aria-labelledby` で関連付ける。
- 画像には内容を説明する代替テキストを設定する。
- キーボード操作時はフォーカス枠を表示する。
- スマートフォンメニューは `aria-expanded` と `aria-label` を状態に合わせて更新する。
- Escapeキーでメニューを閉じ、メニューボタンへフォーカスを戻す。
- `prefers-reduced-motion: reduce` ではスムーズスクロールと遷移を無効にする。
- JavaScriptが動作しなくても、ナビゲーションと主要作品へのリンクを利用可能にする。

- トップ画像を変更する場合は、`style.css` のヒーロー背景、`index.html` のOGP画像とpreloadを同時に確認する。
- 画像を差し替える場合は、同じファイル名で上書きするか、参照箇所をすべて更新する。
- 写真・イラストは表示品質を保ちながらWeb向けに圧縮する。

## 11. 変更箇所の目安

| 変更したい内容 | 主に編集する場所 |
|---|---|
| トップ画像を変更 | `images/`、`style.css`、必要に応じて `index.html` |
| キャッチコピーや紹介文を変更 | `index.html` |
| 作品を追加・削除・更新 | `apps.js`、`images/`、`index.html` の `noscript` |
| 配色や余白を変更 | `style.css` |
| スマホメニューの動作を変更 | `navigation.js` |
| XのURLを変更 | `index.html` 内の2箇所 |
| OGPや検索結果の文言を変更 | `index.html` の `<head>` |
| 作品詳細ページを追加 | `apps/` 配下と `apps.js` |

## 12. 公開方法

1. 変更用ブランチで修正する。
2. 表示とリンクを確認する。
3. Pull Requestを作成する。
4. `main` ブランチへマージする。
5. GitHub Pagesの反映後、https://noburick.github.io/ を確認する。

GitHub Pagesは `main` ブランチのリポジトリ直下を公開対象とする。通常、マージ後の反映には数分かかる。
